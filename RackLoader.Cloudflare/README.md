# RackLoader Publisher Worker

Cloudflare Worker обслуживает сайт кабинета, реестр издателей и удалённую подпись манифестов `.rkm`. Данные хранятся в D1. Приватные RSA-ключи шифруются AES-256-GCM до записи в базу.

## Первый запуск и деплой

Требуются Node.js 22 или новее, npm и аккаунт Cloudflare. Из каталога этого проекта запустите:

```powershell
cd D:\Dev\RackLoader\RackLoader.Cloudflare
npm run deploy
```

Скрипт установит Wrangler, откроет авторизацию Cloudflare, создаст D1, применит миграции, настроит секреты и опубликует Worker вместе с сайтом. После первого входа в браузере подтвердите доступ Wrangler и дождитесь окончания деплоя.

В конце скрипт напечатает URL сайта и административный токен. Откройте сайт и введите токен на главной странице. URL также будет записан в `.deployment/worker-url.txt`; упаковщик и плагин подхватывают его автоматически. При сборке решения с `-p:DeployToGame=true` этот URL копируется рядом с плагином.

Каталог `.deployment` исключён из git. В нём находятся административный токен, URL и ключ шифрования приватных ключей издателей. Сделайте его резервную копию в защищённом месте. Если D1 уже настроена, но локальная копия `key-encryption-key` потеряна, деплой намеренно остановится: новый ключ не сможет расшифровать имеющиеся издательские ключи.

Повторный `npm run deploy` обновляет Worker и миграции, сохраняя существующие ключи и базу.

## Выпуск ключа издателя

1. Войдите с административным токеном из вывода деплоя.
2. Выпустите одноразовую ссылку, указав метку издателя и, при необходимости, `RackModId`, который разрешено подписывать этим ключом.
3. Передайте ссылку разработчику. Она истекает через выбранный срок и активируется один раз.
4. Разработчик открывает ссылку и нажимает **Активировать ключ**. Форма и ручной ввод не требуются; токен `RACKLOADER_DEVELOPER_KEY` появляется только после активации и показывается один раз.
5. После компрометации токена отзовите издателя. Новые подписи прекратятся, а список доверенных ключей исключит его.

Секрет разработчика показывается один раз. Worker хранит только SHA-256 хеш токена. Закрытый RSA-ключ зашифрован AES-256-GCM и никогда не выдаётся браузеру или упаковщику. В Worker создаётся RSA-PSS ключ 3072 бит; подписываются исходные байты `manifest.json` алгоритмом RSA-PSS/SHA-256 с 32-байтовой солью.

## Упаковка из проекта мода

Подключи NuGet `RackLoader.ModSdk` и укажи метаданные мода. Пакет добавляет интерфейс `IRackMod`, ссылки на API установленной игры и BepInEx, а после обычного `dotnet build` создаёт `.rkm`:

```xml
<ItemGroup>
  <PackageReference Include="RackLoader.ModSdk" Version="1.0.1" />
</ItemGroup>
<PropertyGroup>
  <RackModId>example.weather</RackModId>
  <RackModName>Example Weather</RackModName>
  <RackModVersion>1.2.0</RackModVersion>
  <RackModEntryType>Example.WeatherMod</RackModEntryType>
</PropertyGroup>
```

Передай `RACKLOADER_DEVELOPER_KEY` как секрет CI или локальную переменную окружения. Не сохраняй токен в `.csproj`:

```powershell
$env:RACKLOADER_DEVELOPER_KEY = "rkd_..."
dotnet build .\ExampleWeather.csproj
Remove-Item Env:RACKLOADER_DEVELOPER_KEY
```

Сборка упаковывает и удалённо подписывает мод. Адрес текущего Worker задан в SDK; для другого сервера укажи `RackModSigningServiceUrl` или `RACKLOADER_SIGNING_URL`. Дополнительно см. `RackLoader.ModSdk/README.md`.

Для локальной подписи можно задать `RackModPrivateKey` и `RACKLOADER_RKM_KEY_PASSWORD`. Неподписанный архив собирается с `<RackModUnsigned>true</RackModUnsigned>`; загрузка такого архива возможна только при `AllowUnsignedMods=true` в конфиге RackLoader.

SDK готовится к публикации командой `RackLoader.ModSdk/publish.ps1`. Для отправки на nuget.org установи переменную `NUGET_API_KEY` и явно передай скрипту `-Push`.

## API

- `GET /api/health` — проверка доступности.
- `GET /api/trusted-keys` — активные публичные ключи издателей. Плагин сверяет fingerprint с SPKI и сохраняет локальный кэш на случай временной недоступности сети.
- `POST /api/enroll` — одноразовая регистрация по приглашению; токен возвращается только в ответе регистрации.
- `POST /api/sign` — подпись манифеста с Bearer токеном разработчика.
- `POST /api/admin/invites`, `GET /api/admin/developers`, `POST /api/admin/revoke` — административные операции с Bearer административным токеном.

Отзыв распространяется при следующем успешном обновлении списка доверенных ключей клиентом. Если клиент долго офлайн, он продолжает использовать локальный кэш; загрузка неподписанных пакетов — отдельный переключатель `AllowUnsignedMods` и по умолчанию выключена.
